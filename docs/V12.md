# CFW v12: real head-up/down events

`GLASSLYCFW-IO/12` uses the same pinned Strix OS 1.0.4.12 base as v11.
It has been built and host-tested, but has not been flashed or hardware-validated.

## Cause and change

The stock sensor already reports head up and down to the launcher, but it does
not forward these events over RNLink. CFW previously relayed only crown/button
input. Both Glassly drivers also lacked head-event mappings, left the angle
setter empty, and emitted a single synthetic head-up event on connection.

The new hook replaces the byte-verified `bl` at `0x106EB518` in
`LauncherThreadMsgHandler::handleHeadUpDownEvent`. It calls the original
`SysStateMonitor::notifyHeadUpDownEvent` (`0x106DD4A9`) and then relays direction
2 as event 12 (`head_up`) and direction 1 as event 15 (`head_down`). Source 2
identifies the head detector. Unknown directions are ignored by the relay.
The hook runs on the launcher UI thread, so it uses the existing uplink queue
without introducing a sensor-thread writer. It requires a prior CFW QUERY,
works with the Glassly page closed, and flushes immediately. It preserves the
stock sensor callbacks and stock wake/DND handling. Glassly receives detector
events even when stock DND suppresses the stock wake action.

IDENT bit 6 (`0x40`) advertises head events and control 7. The control's required
argument is an angle in degrees, clamped to 0..90. It updates only the stock
head threshold (preference `0x2e`) and head wake enable (`0x2d`), leaving crown
wake (`0x2f`) alone, then calls `SysStateMonitor::applyWakeupConfig`. That stock
function handles the sensor RPC's hard-float ABI. Unchanged preference values
are not rewritten; configuration is reapplied on reconnect. Failed writes or
an absent monitor stop application of the configuration. These head settings
persist in the stock preferences, as they do through the stock settings UI.

Both Glassly SDKs map events 12/15, send the saved head angle after capability
detection, and support subsequent angle changes. They retain the synthetic
connect-time head-up only on firmware without the new capability.

## Local validation

- `tools/host/run_head_tests.sh`: ASan/UBSan checks real packet encoding, stock
  forwarding, query gating, closed-page delivery, reserved reply slots, angle
  bounds, write failure handling, and preservation of crown preferences.
- `./build_cfw.sh`: symbol/address and displaced-instruction verification,
  committed-patch replay, module reproduction, AP size/footer/hash checks,
  OTA repacking, and artifact integrity checks.
- iOS SDK cross-build; 10 focused Swift tests, including 3 head-event tests.
- Android public SDK AAR build; head-event and firmware classification tests.

## Hardware validation path (pending)

1. Install a Glassly build containing the v12 phone drivers and bundled image;
   flash v12 using its normal RayNeo firmware flow, reconnect, and confirm
   `GLASSLYCFW-IO/12` with IDENT bit 6 in the device log.
2. With the dashboard closed, lower then raise your head past the configured
   angle. Check a `head_up` event opens it; lower your head and verify a
   `head_down` event reaches the active handler. Repeat with the screen asleep.
3. Change the head angle (for example, 20 then 45 degrees). Confirm the physical
   trigger follows the setting, then disconnect/reconnect and repeat. Confirm
   the stock crown wake setting is unchanged.
4. Check stock wake behavior and DND, crown scrolling, button taps, and long
   holds. Confirm head events do not also produce button-press events. Run the
   existing `tools/suite` hardware checks after flashing.
5. Reconnect with v11 or stock firmware to check the legacy connect-time
   dashboard behavior and that no unsupported angle control is sent.
