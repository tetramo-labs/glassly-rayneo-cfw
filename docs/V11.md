# Revision 11

`GLASSLYCFW-IO/11` is a firmware build for the pinned Strix OS 1.0.4.12 base.
It includes the working-tree revision 10 microphone and heap changes. It is
host-tested; this revision has not been flashed or measured on glasses.

## Correctness fixes

- Asset chunks are checked against the allocation's original kind and length,
  with subtraction-based bounds checks. Holes and conflicting retransmissions
  are refused; identical chunks remain idempotent across lenses and retries.
- A replacement uploads alongside its previous complete version. Images and
  font tables validate before publication. Capacity failure preserves the old
  asset, and both lenses resolve the replacement only after completion.
- PUT and inline SHOW mutations use an undo log. Refusal or capacity failure
  restores definitions, evictions, store ownership and journal revisions. Live
  store granules are copied only if an allocation will overwrite them; upload
  tails beyond the previous filled length remain invisible on failure. The
  transaction metadata is about 6 KiB, plus touched objects and overwritten
  store bytes. Allocation failure refuses the message. Animation-only SHOWs
  need no transaction allocation.
- Animation backpressure is sampled once per stereo tick. Both eyes draw under
  a presentation hold and request one present afterward. The left eye can no
  longer set the pending flag that causes the right eye to skip its frame.
- PATH MOVE/GLIDE now use the path's p0/p1 coordinate masks.

## Why screen opening and updates were slow

The existing hardware investigation in RAW-LINK-PLAN.md records a starved UI
loop (roughly 190 ms iterations before the revision 9 wake changes), first
text-heavy renders exceeding 255 ms per eye, and display conversion around
55 ms. These are historical measurements, not new v11 measurements. Input
polling, packet processing and scene drawing share that UI thread, so a long
render delays ACKs and can also defer input delivery.

The current phone driver waits for PAGE_OPEN, an initial cache RESET, and each
queued upload/SHOW. Its normal writes use BLE without response, with platform
backpressure; there is no intentional delay between normal screen-update
packets. Separate assets still incur serialized upload/ACK round trips.
The new timing probe's eight-line builtin-text screen is 623 decoded bytes,
196 compressed record bytes: one 240-byte packet. Large images/fonts are a
different workload; the probe does not establish that all screens are cheap
to transfer.

V11 removes repeated work in the firmware:

- Identical eye draw states rasterize once and copy the completed canvas to
  the other eye. Different depth positions, text, assets, rotations or animation
  phases still render separately. Stale, hidden and raster-owned canvases are
  excluded from reuse.
- Canvas copies/clears use aligned words, with byte paths for alignment and
  tails. The LCDC converter packs four L8 pixels per iteration; its 302-byte
  destination stride only requires 16-bit alignment.
- STATE queries and duplicate SHOW retries preserve the static-layer cache.
  Advancing animation invalidates the finished canvas without invalidating
  the static prefix behind moving objects.
- Packet processing holds presentation while finishing its records, avoiding
  a presentation request between the two eyes' SHOWs in the same packet.

No on-device speedup or optical frame rate is claimed yet. DIAG now appends
render/copy counts and last/max scene-render milliseconds at byte 39, keeping
its old prefix compatible. The display-hook and animation timing counters
remain available in SETTLED.

## Validation and measurement

Run the Python tests and all six host suites (image, raster, vector, compass,
cache, memory). Cache/memory coverage includes allocator failures, eviction
rollback, malformed RLE/font offsets, repeated chunks, stereo backpressure,
flat-eye reuse, every memory alignment/tail, overlapping copies and every L8
gray level. C host suites run with AddressSanitizer and UndefinedBehaviorSanitizer.
The firmware build cross-compiles for Cortex-M33, resolves its own relocations,
asserts the stock hook bytes, and enforces the AP size/footer constraints.

After installation and the regular on-device suite, start the SDK Mac bridge
and run:

```sh
cd tools/g2suite
bun scene-timing.ts --dry-run  # offline payload sizes
bun scene-timing.ts            # PAGE_OPEN, RESET, first and repeated SHOW ACK latency
bun anim-timing.ts             # animation duration, compose/update times, skipped frames
```

`scene-timing.ts` prints six samples per workload and the v11 render counters.
ACK timing includes firmware drawing and transport, but is not a measurement
of optical presentation. Compare the same light and eight-line screens with
the earlier firmware, then inspect compose/update timing if presentation still
lags after the ACK improves.
